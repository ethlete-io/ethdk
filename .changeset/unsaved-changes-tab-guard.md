Guard the browser tab in the `unsavedChanges` family, and coordinate guards app-wide - an in-app guard alone still loses edits to <kbd>Ctrl</kbd>+<kbd>W</kbd> or a reload, and several guards in one app used to stack dialogs and strand them.

- `createUnsavedChangesTracker` (and therefore `createUnsavedChangesGuard` / `createOverlayUnsavedChangesGuard`) now **locks the tab by default** while the watched value differs from its baseline: a `beforeunload` listener makes the browser show its own "Leave site?" confirmation. It is attached only while changes exist, so a clean page stays eligible for the back/forward cache. Configure via the new `tab` option, or pass `tab: false` to opt out; `tracker.tab` exposes the guard so it can be released early (e.g. before a deliberate `location.reload()`).
- `tab` extras, all opt-in: `titleMarker` prefixes the tab title while dirty (`true` → `'●'` / `UNSAVED_CHANGES_TITLE_MARKER`, or a custom string), `flash` blinks that marker while the tab is backgrounded (`{ interval?, whenHidden? }`), `favicon` draws a dot on the favicon, and `badge` sets an app badge via the Badging API (`true` → dot, a number → count; installed apps only, counts from several trackers add up).
- `createUnsavedChangesTabLock({ hasChanges, lock?, titleMarker?, flash?, favicon?, badge? })` is the same guard standalone, for "unsaved" state that isn't a form - pending uploads, a queued draft, an in-flight mutation.
- New `injectUnsavedChangesCoordinator()`: **one confirm on screen at a time** app-wide (a check that starts while another confirm is up adopts its decision instead of opening a second dialog, `isCheckPending` reads whether one is up), and `abandonAll(reason?)` for a session that ends underneath a guard - it resolves the pending check as "discard allowed", aborts the confirm's `AbortSignal`, and switches every live guard off (checks pass, tab locks release). `@ethlete/query`'s auth provider calls it on logout. Trackers expose `isAbandoned`, and `confirm` now receives a second `{ signal }` argument so a dialog can close itself instead of being stranded.
- Title store: new `addMarker` / `removeMarker` plus the public `applyHeadTitleMarker(binding)` binding - a short marker prefixed onto the composed title, outside the divider logic (`● Editor | App`), deduplicated across registrations. The store's `defaultTitle` now also falls back to the initial `document.title` when the configured default is an empty string, so a lazily created store no longer wipes a title that came from `index.html`.
- New favicon store + `applyFaviconOverlay(binding)`: draw a `dot` or a `progress` ring (0–100) on the site's favicon, restored when the binding empties. Colors default to `--et-theme-color-primary-solid`. This is as close as the web gets to tab progress - no browser exposes a taskbar progress or "demand attention" API. Cross-origin icons that taint the canvas leave the favicon untouched instead of breaking it; SSR draws nothing.
