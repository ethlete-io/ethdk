Add a type-safe, light-by-default **Table** component (`et-table`, `TABLE_IMPORTS`).

Columns are declared with the typed helper `tableColumns<T>()`, so the row type flows into every `value` accessor (and, via each column's `key`, into serializable state) without wiring templates to data by string. Rows and cells render on a CSS grid with a sticky header; the table is its own scroll container (give it a bounded height to scroll a body under the pinned header). Colors come from the surface theming tokens, and any cell can hold custom content via `cell` / `headerCell` templates.

- **Appearance & density**: `appearance` (`'enclosed'` default, `'divided'`, `'zebra'`, `'grid'`, `'bare'`) and `density` (`'sm'`, `'md'` default, `'lg'`).
- **Sorting**: `sortable` columns with tri-state `aria-sort` headers (an animated two-chevron sort glyph), a two-way `sort` state, `multiSort`, and `sortMode` `'client'` (exported `sortRows`) / `'server'`.
- **Filtering** (opt-in, `TABLE_FILTER_IMPORTS`): drop `<et-table-filters />` inside the table to give `filterable` columns a multi-select menu, with in-menu search and async/paginated options. It carries the menu system, so it is a separate component — a table without it never pulls that in. Filter state stays on the table (two-way `filters`, `filterMode` `'client'` via the exported `filterRows` / `'server'`), so `state()` / `restoreState()` round-trip filter values regardless.
- **Row expansion**: `expandedRowTemplate` renders lazy, reduced-motion-aware detail rows (nest a table for sub-tables); `expandableRow` gates rows, `expandedKeys` is two-way. The detail row fades and slides into place with `opacity`/`transform` only — the two properties the compositor animates on its own — instead of animating the cell's grid track, which re-resolved the whole table grid on every frame. Measured per toggle on a 20-row table at 20× CPU throttle: ~20ms average frame and 3 long frames, against ~41ms and 5–6 before. Only the row the user actually toggled animates: a detail row that re-mounts because the rows changed (paging, sorting, a query refresh) appears and disappears instantly instead of replaying an open the user never asked for.
- **Selection** (opt-in, `TABLE_SELECTION_IMPORTS`): drop `<et-table-selection [(selection)]="…" />` inside the table for a leading checkbox column, with a select-all/indeterminate header, `selectableRow` gating and configurable `selectAllLabel` / `rowLabel`. It carries the checkbox component, so a table without selection never pulls that in.
- **Row navigation**: `rowInteractive` gives rows a pointer/hover affordance and emits `(rowClick)` with the row (keyboard-activatable); clicks on interactive cell content (buttons/links/inputs/menu triggers/select/expander cells) are ignored via `composedPath`. Navigation stays the consumer's job.
- **Column reordering** (opt-in, `TABLE_REORDER_IMPORTS`): drop `<et-table-reorder />` inside the table for drag-to-reorder headers, with a floating ghost preview and a deferred, animated drop. Pinned columns are excluded so they can't be stranded mid-scroll. Column visibility (`moveColumn` / `setColumnVisible` / `toggleColumnVisibility`) stays on the table itself.
- **Resizable columns** (opt-in, `TABLE_RESIZE_IMPORTS`): drop `<et-table-resize />` inside the table for a header grip (enlarged for touch) that drags column widths, clamped between a minimum and the table's own width, double-click to reset. Widths persist in `state()` (`TableColumnState.width`), travel with a column when it's reordered, and compose with reordering.
- **Grouped headers**: a column `group` spans adjacent columns under one label in a second header row; each sub-column stays independently sortable/filterable.
- **Sticky columns & footer**: `sticky: 'start' | 'end'` pins columns during horizontal scroll — auto-suspended on viewports too narrow to leave the other columns room, so they never cover the whole width; a column `footerCell` renders a bottom-pinned summary row.
- **Footer slot**: project `[etTableFooter]` for a full-width bar below the grid (pinned to the scroll bottom, rendered only when used) — drop in an `<et-pagination>` + page-size `<et-select>` and wire them to `tableRowsFromQuery`. In a table with a bounded height the bar sits at the bottom of the box even when the rows don't fill it (the grid area absorbs the slack instead of leaving dead space under the bar), and row heights stay driven by `density` alone.
- **Root-font independence**: the table's own metrics (cell padding, text sizes, chrome) are px rather than root-relative `rem`, matching the rest of the library — identical at a 16px root, no longer shrunken in apps that set a smaller one (e.g. the `62.5%` trick). That includes the leading utility columns (`--et-table-expander-width` / `--et-table-select-width`, now `32px`), which at a smaller root squashed the 24px expander button to 19.5px wide; the expander and the selection checkbox also no longer shrink below their own size whatever those tracks are set to.
- **Virtualization** (opt-in, `TABLE_VIRTUAL_SCROLL_IMPORTS`): drop `<et-table-virtual-scroll [estimateRowHeight]="…" [overscan]="…" />` inside the table to render only the rows near the viewport, with spacers keeping the scrollbar honest.
- **State**: versioned `state()` / `restoreState()` capture column order, visibility, sort, filters, width and expanded rows and round-trip losslessly; `serializeTableState` / `deserializeTableState` make a table shareable as a URL query param.
- **Query integration**: `tableRowsFromQuery` (and the legacy `tableRowsFromV2Query` twin) feed the table from an `@ethlete/query` query with server-side sort/filter/pagination.

`TABLE_IMPORTS` is the lean base (rows, cells, sort headers, sticky columns, empty state, footer slot); optional features ship their own imports array and register themselves with the table through `TableFeatureHost`, so what you don't import stays out of your bundle. Every optional feature is now extracted: filtering (`TABLE_FILTER_IMPORTS`, carries the menu system), resizing and reordering (`TABLE_RESIZE_IMPORTS` / `TABLE_REORDER_IMPORTS`, the drag primitives), selection (`TABLE_SELECTION_IMPORTS`, the checkbox) and virtual scrolling (`TABLE_VIRTUAL_SCROLL_IMPORTS`, the virtual-window utility). The base table's own `imports` is down to `NgTemplateOutlet`, and each feature ships its own styles too, so an unused feature contributes no CSS either.

Features plug into three seams on the table — header adornments, leading utility columns and a rows window — and the serializable state they drive (filter values, column widths) stays on the table, so `state()` / `restoreState()` round-trip regardless of which features a consumer imported. Sorting, row expansion, sticky columns, the footer slot and the empty state remain part of the base.

Measured in an application build, gzipped: a base table is **57.3 kB** where it used to be 69.3 kB with everything baked in, and each feature is billed to whoever imports it — resize +0.5 kB, virtual scroll +0.7 kB, reorder +1.2 kB, selection +2.8 kB, filters +8.8 kB (the menu system), +14.0 kB for all five.
