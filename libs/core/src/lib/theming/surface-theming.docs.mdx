# Surface Theming — Design Specification

Surface themes define the background, text hierarchy, border, and interaction colors for a UI surface (page, card, panel, toolbar). Surfaces are elevation-aware — nested surfaces know their depth in the stack.

---

## What is a surface theme

A surface theme is a named set of tokens for a complete UI layer. Unlike color themes (which drive component accent colors), surface themes drive the canvas that components sit on: background, text, and borders. Components automatically adapt their ink colors to the active surface.

---

## SurfaceTheme structure

<table>
  <tr>
    <td>Field</td>
    <td>Type</td>
    <td>Description</td>
  </tr>
  <tr>
    <td>`name`</td>
    <td>`string`</td>
    <td>Identifier used to apply the surface (e.g. `'dark'`, `'light-elevated'`)</td>
  </tr>
  <tr>
    <td>`type`</td>
    <td>`'light' | 'dark'`</td>
    <td>Overall luminosity — used for automatic contrast decisions</td>
  </tr>
  <tr>
    <td>`elevation`</td>
    <td>`number`</td>
    <td>Stack depth: 0 = base, 1 = raised, 2 = higher. Components can request "next elevation" automatically.</td>
  </tr>
  <tr>
    <td>`isDefault?`</td>
    <td>`boolean`</td>
    <td>
      Applied when no explicit surface input is set. The CSS generator's `--defaultLightTheme=<name>` /
      `--defaultDarkTheme=<name>` options override these flags per surface type, so apps sharing one theme set can
      each pick their own defaults at generation time.
    </td>
  </tr>
  <tr>
    <td>`background`</td>
    <td>RGB</td>
    <td>Background fill color</td>
  </tr>
  <tr>
    <td>`color`</td>
    <td>RGB</td>
    <td>Primary text color</td>
  </tr>
  <tr>
    <td>`colorMuted`</td>
    <td>RGB</td>
    <td>Secondary / supporting text</td>
  </tr>
  <tr>
    <td>`colorSubtle`</td>
    <td>RGB</td>
    <td>Tertiary / placeholder text</td>
  </tr>
  <tr>
    <td>`border`</td>
    <td>RGB</td>
    <td>Divider and border color</td>
  </tr>
  <tr>
    <td>`tint?`</td>
    <td>RGB</td>
    <td>The source hover and pressed feedback mixes into a neutral control on this surface</td>
  </tr>
  <tr>
    <td>`controlText?`</td>
    <td>RGB per state</td>
    <td>
      The text of a neutral control per state (`default`, optional `hover`, `focus`, `active`, `disabled`); also the
      fill `[etProvideColor]="'surface'"` resolves
    </td>
  </tr>
</table>

Color values use space-separated channel numbers (same format as color themes): `"R G B"`.

```ts
tint: '115 115 115',
controlText: { default: '115 115 115', hover: '64 64 64', focus: '64 64 64', active: '23 23 23', disabled: '180 180 180' },
```

## Registration

```ts
provideSurfaceThemesWithTailwind4([DARK_SURFACE, LIGHT_SURFACE, DARK_ELEVATED_SURFACE, DARK_ELEVATED_2_SURFACE]);
```

---

## Applying a surface

```html
<div etProvideSurface="dark">...</div>
<div [etProvideSurface]="myCustomSurfaceName">...</div>
```

The directive accepts a registered surface theme name and sets the surface context. All components inside inherit the surface tokens.

## CSS tokens generated

When a surface is active, these custom properties are available to descendants:

<table>
  <tr>
    <td>Token</td>
    <td>Role</td>
  </tr>
  <tr>
    <td>`--et-surface-background`</td>
    <td>Background fill (use this for `background-color`)</td>
  </tr>
  <tr>
    <td>`--et-surface-text`</td>
    <td>Primary text color</td>
  </tr>
  <tr>
    <td>`--et-surface-text-muted`</td>
    <td>Secondary text color</td>
  </tr>
  <tr>
    <td>`--et-surface-text-subtle`</td>
    <td>Tertiary text color</td>
  </tr>
  <tr>
    <td>`--et-surface-border`</td>
    <td>Border / divider color</td>
  </tr>
  <tr>
    <td>`--et-surface-tint`</td>
    <td>
      Neutral hover/active tint source; mix it, e.g. `color-mix(in srgb, var(--et-surface-tint) 12%, transparent)`
    </td>
  </tr>
</table>

Every token above is a ready color. Derive translucent values with `color-mix()`.

## Elevation nesting

Surfaces can be nested. The surface provider hierarchy carries the current elevation — a component inside a `dark` (elevation 0) surface can request elevation 1 and automatically receive `dark-elevated` without being explicitly told which surface to use.

In Figma: model elevation levels as separate frames/components with their own surface variable modes. Nesting a raised card inside a base page automatically applies the elevation-1 mode.
