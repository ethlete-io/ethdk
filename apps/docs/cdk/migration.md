# Migrating from the CDK, symbol by symbol

Every public `@ethlete/cdk` export and what it becomes in [`@ethlete/components`](/components/) or
[`@ethlete/core`](/core/). For the domain-level view - which cdk area is superseded by which guide -
start at the [CDK overview](/cdk/#superseded-by-ethlete-components); this page is the lookup table for
a single identifier.

The rows come from `migration-map.json`, which ships inside the `@ethlete/cdk` package (so a
migrating app already has it on disk, at `node_modules/@ethlete/cdk/migration-map.json`). A spec in
that library asserts every public barrel export appears in the map exactly once, and that every key is
a real export - a symbol missing here means the map is out of date, not that the symbol has no
successor.

::: warning Read this before concluding "there is no replacement"
Migrating one real 47-file app by diffing `.d.ts` exports got **nine** symbols wrong the same way:
a name that disappeared was read as a feature that disappeared. Three patterns cause almost all of
those false negatives, and each gets its own section below - the
[`FooImports` casing change](#imports-arrays), the
[utilities that moved to `@ethlete/core`](#moved-to-core), and the
[concept renames](#concept-renames).
:::

## How to read the tables

| `kind`           | Rows | What it means                                | What the diff looks like                      |
| ---------------- | ---- | -------------------------------------------- | --------------------------------------------- |
| `move`           | 153  | Same name, new package                       | Change the import path                        |
| `rename`         | 47   | Same shape, new name                         | Change the import path and the identifier     |
| `reshape`        | 53   | Same name and package, changed contract      | Call sites need edits - read the note         |
| `rename+reshape` | 77   | New name **and** changed contract            | Both of the above                             |
| `replaced-by`    | 117  | A differently shaped API covers the use case | A rewrite against the successor               |
| `removed`        | 180  | No successor                                 | Delete it, or rebuild on the new architecture |

- Successors live in `@ethlete/components` unless the row says `@ethlete/core`, and each one links to
  the guide that documents it.
- **`requires @ethlete/components ≥ x`** marks a successor that landed later than the map itself: on
  an older version the target of that row does not exist yet.
- A `—` in the last column means the map records nothing beyond the name or package change. It is not
  a promise of an identical contract for `reshape` and `replaced-by` rows - the linked guide is the
  contract.
- The three pattern sections below are **views, not a partition**: a row can appear in two of them, and
  the [full symbol index](#full-symbol-index) then lists it once more. The index is the complete one -
  all 627 symbols, each exactly once.

::: tip Reactive forms are not a blocker for the unsaved-changes family
`createUnsavedChangesTracker` / `createUnsavedChangesGuard` take a `source`, and
[`UnsavedChangesSource<T>`](/core/utilities#unsaved-changes) accepts a signal-forms `FieldTree<T>`,
a `Signal<FieldTree<T> | null>` for late/async forms, an **`AbstractControl`**, or a
`WritableSignal<T>`. An `AbstractControl` is bridged internally to a read signal plus a writer, so
an app still on classic reactive forms can move off `createNavigationDismissChecker` and
`createFormChangesTracker` **before** it migrates to signal forms. The signal-forms migration is not
a prerequisite - which is worth knowing, because the reverse assumption is the natural one to make.

```ts
export class EditorPage {
  protected form = inject(FormBuilder).group({ name: [''] });

  // A FormGroup / FormControl / FormArray - no signal forms involved.
  private guard = createUnsavedChangesGuard({
    source: this.form,
    confirm: () => this.confirmDiscard(),
  });
}
```

Two differences from `createNavigationDismissChecker`: `confirm` replaces `dismissCheckFn` and is
**required per call site**, and the returned ref adds `canDeactivate()` for a route guard plus a
`beforeunload` tab lock that is **on by default** (`tab: false` opts out).
:::
