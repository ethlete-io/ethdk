# eslint-plugin lib scan — noteworthy findings

Scan date: 2026-08-19. Scope: all of `libs/eslint-plugin` — 58 rules (~9.6k lines of non-spec
source), the three shared `internals/` helpers, the `recommended` config, the packaging files,
the two docs pages under `apps/docs/eslint`, and the `docs/STYLEGUIDE.md` sync the plugin's own
CLAUDE.md mandates. Seven parallel review agents read the source. Each agent verified every High
and Medium claim at runtime with ESLint's `Linter`/`verifyAndFix` (TS inputs through
`@typescript-eslint/parser`, templates through `@angular-eslint/template-parser`), including
re-parsing fixer output. The full test suite is green (59 files / 792 tests), so none of the
findings below is caught by an existing spec.

Severity counts: **25 high**, **66 medium**, **~68 low**.

## Summary of the worst problems

1. The two accessibility fixers insert `public `/`private ` directly before the member key, so any getter, setter, `static`, `readonly`, `override`, `async`, `declare` or computed-key member becomes unparseable after `--fix` — 42 files of `libs/cdk` stop parsing in one verified run — and a decorated member gets its decorator mangled into `publicHostListener(...)`. Both rules ship as `error` + fixable in `recommended`. (template-member-accessibility, inject-member-accessibility)
2. A whole class of fixers emits code that no longer compiles: `no-type-only-import` breaks aliased/default/namespace type imports, `no-redundant-on-push-change-detection` deletes the `ChangeDetectionStrategy` import while `CDS.OnPush` or a `TestBed.overrideComponent` still references it (and crashes outright on a default+named import), `no-readonly-signal`'s token hunt eats a decorator property, and four metadata rules silently delete a `...spread` from `@Component({ … })`. (bans, ng-metadata, reactive)
3. Fixes that silently change behavior: `no-standalone-flag` removes `standalone: false` (a spec locks this in as correct), `no-effect-cleanup-return` rewrites a conditional early `return` into a fall-through, `no-legacy-angular-decorators` turns `@HostBinding(CONST)` into a wrong host binding, `no-trivial-return-type` widens the declared return type of concise-body arrows in published `.d.ts`, `inject-member-accessibility` narrows an abstract base's `protected` inject to `private` and breaks every subclass, and `no-redundant-internal` deletes the entire JSDoc block instead of the tag. (ng-metadata, reactive, misc, visibility)
4. A cross-rule `--fix` deadlock reachable from the shipped config: `require-view-encapsulation-none` × `no-redundant-on-push-change-detection` leave an unused `ChangeDetectionStrategy` import that neither rule will ever report again, so `nx lint --fix` ends with a hard `no-unused-vars` error on an ordinary component. `RuleTester` can never see it — no cross-rule spec exists. (ng-metadata)
5. The published `recommended` config runs every DOM/platform ban at `error` inside `**/*.spec.ts`; `recommendedSpec` relaxes exactly one rule (one that typescript-eslint's `recommended` doesn't even enable). The SDK's own libs escape only via per-lib `ignores` lists the shipped config does not carry, so a consumer following the documented "simplest setup" cannot write a normal Angular test without disable comments. (dom, bans, misc)
6. Rules steer consumers to replacements that do not exist or do not do the job: `no-angular-seo-services` names three `@ethlete/core` exports that were never shipped (`injectTitleBinding` & co. — the real API is `applyHeadTitleBinding`/`applyMetaBinding`/`applyLinkBinding`), `no-legacy-query-import` points `provideQueryDevtools()` at the wrong package, `prefer-match-media` claims two one-shot boolean helpers "return reactive signals", `prefer-scroll-state` recommends an API that exposes no scroll position (and names `@ethlete/cdk`, the maintenance-mode lib), `no-locale-id` bans the legitimate `{ provide: LOCALE_ID }` registration and mislabels `injectLocale()` as a wrapper, and `prefer-viewport-size` flags `window.screen`/`outerWidth`, which its replacement cannot provide. (bans, dom)
7. Contract-blind false positives at `error`: `no-trivial-wrapper-method` and `no-member-alias` flag `ControlValueAccessor`/interface/abstract-override members that external code calls by name (including the `ngTemplateContextGuard` the same config whitelists), `no-pipe-logic` reports TS overload signatures that contain no logic, `no-unused-class-member` reports `override` hooks, decorated setters and destructured reads, and `class-constant-property` force-`readonly`s a mutable `[]`/`{}` buffer and then demands SCREAMING_CASE with no fixer. (misc, visibility, ordering)
8. `prefer-static-boolean-properties`' suggestion inverts native HTML semantics: `[disabled]="false"` → `disabled="false"` is a disabled button, `[checked]="false"` → a checked checkbox. (misc)
9. `require-form-submit` cannot see across component boundaries, so a projected or `ng-template`-hosted `type="submit"` button — the normal shape for reusable form actions — is an error with no compliant rewrite. (dom)
10. Comment-handling in fixers is systematically unsafe: `guard-return-newline` detaches a trailing comment instead of adding the blank line, both reordering fixers re-attach trailing comments to the wrong member/property, the host-directives fixes drop comments, and the import rebuilds flatten and lose them. No spec anywhere asserts that fixer output re-lints clean, still parses, or preserves comments. (ordering, ng-metadata)
11. Name-only matching without import or scope resolution is the plugin-wide root cause of most false positives/negatives: `effect`/`Component`/`Title`/`document`/`setTimeout`/`.set()`/`.subscribe`/`.pipe` are matched as bare tokens, aliased imports (`Component as Cmp`, `effect as ngEffect`, `ChangeDetectionStrategy as CDS`) defeat nearly every rule, and re-exports/dynamic imports are invisible to every import ban. (all groups)
12. Packaging and meta drift: peer dependencies are exact-pinned to `@angular/core 22.0.7`/`typescript 6.0.3` (the OnPush rule exists specifically for Angular ≤ 21 consumers, who cannot satisfy the range), `tslib` is a dead peer, the plugin's `meta.version` says `0.0.1` at package version `1.0.0-next.22`, and 13 registered rules are missing from `docs/STYLEGUIDE.md`'s mandatory "Enforced by lint" table. The VitePress rule tables, by contrast, are exactly in sync (58/58, severities and 🔧 flags all correct). (misc)

## ordering & naming

(class-member-order, class-constant-property, angular-decorator-property-order, no-empty-newlines-between-imports, guard-return-newline, no-leading-underscore-class-member, no-screaming-case-local, require-dollar-suffix)

### High

- **`guard-return-newline`'s fixer "fixes" a trailing comment instead of inserting the blank line, permanently detaching the comment from its statement.** `guard-return-newline.js:70-73` inserts `\n` after the _last token_ of the previous statement, but the line-gap check at `:58-62` measures `prevStatement.loc.end.line` vs `node.loc.start.line`, so a same-line trailing comment satisfies the gap without any blank line existing. Verified at runtime: input `if (!x) {\n    doA(); // side effect\n    return;\n  }` → fixed output `doA();\n // side effect\n    return;` — no blank line was added, the rule stops reporting, and the comment is now a standalone line that no longer reads as belonging to `doA()`. Prettier only re-indents it; the comment is not restored. Trailing `// why` comments on the statement before a guard `return` are common consumer code, and `--fix` silently rewrites them.
- **`no-leading-underscore-class-member` collapses `_x` and `__x` to the same name, emitting a class with two identically named members.** `getFixedName` (`no-leading-underscore-class-member.js:7`) strips _all_ leading underscores (`/^_+/`), and `canFix` (`:78-81`) only checks a collision against `frame.declaredNames` — the pre-existing names — never against the other rewrites the same fix batch produces. Verified at runtime: `class Foo { private _value = 0; private __value = 1; }` → `class Foo { private value = 0; private value = 1; }` (both fixes applied in one pass; TS2300 duplicate identifier).
- **`class-constant-property` classifies mutable collection fields as "class constants", auto-adds `readonly`, then emits an unfixable SCREAMING_CASE error.** `isConstantExpression` (`class-constant-property.js:114-139`) treats every `ArrayExpression`/`ObjectExpression` of constant elements — including `[]` and `{}` — as constant, and `collectWrittenMembers`/`getWrittenMemberName` (`:167-181`) only records _assignments to_ `this.x`, so mutation through `this.items.push(…)` or `this.cache[k] = v` is invisible (for `this.cache[k] = v` the assignment target's `.object` is `this.cache`, not `ThisExpression`). Verified at runtime: `class C { private items = []; add(x) { this.items.push(x); } }` → autofixed to `private readonly items = []` and then reports, with no fixer, `Readonly class constant 'items' should use SCREAMING_CASE.` Same for `private cache = {}` + `this.cache[k] = v`. The rule is `error` in `recommended` (`src/configs/recommended.js:379`), so a consumer's mutable buffer field is a build-blocking error whose only escape is renaming it `ITEMS`.

### Medium

- **`class-member-order` reports but never auto-fixes any class containing a `static` member, an abstract member, an index signature or a static block — including the two patterns this repo itself sanctions.** `getMemberGroup` returns `null` for `node.static` (`class-member-order.js:101`) and for every non-`PropertyDefinition`/`MethodDefinition` type, and `buildClassOrderFix` bails when `classBodyNode.body.length !== members.length` (`:317-319`). Verified at runtime: `class C { static readonly NAME = 'x'; size = input(0); private service = inject(Service); }` reports `groupOrder` and `verifyAndFix` leaves the file **unchanged** with the error still present; identical for `[key: string]: any;`, `static { … }`, and `declare`/`abstract` members. Not hypothetical: `recommended`'s `no-restricted-syntax` explicitly permits `static ngTemplateContextGuard` (`src/configs/recommended.js:131-135`, used in `libs/query/src/lib/legacy/directives/query.directive.ts:107`), and `libs/components/src/lib/forms/form-field/headless/text-field-control.directive.ts:106` has `public abstract controlType`. Docs advertise the rule as 🔧 (`apps/docs/eslint/rules.md:83`) with no mention of the bail-out. Abstract members are also invisible to the _ordering check itself_, so they can sit anywhere.
- **Both reordering fixers relocate a trailing same-line comment onto the opening-brace line, re-attaching it to the wrong member/property.** Segments run `[previousMemberEnd, memberEnd]` (`class-member-order.js:291-299`) / `[previousComma, propertyEnd]` (`angular-decorator-property-order.js:132-159`), so a comment after a member belongs to the _next_ segment. Verified at runtime: `private calculate() {} // internal helper` above `handleFocus() {}` → the comment lands on the `class C {` line and now annotates `handleFocus`; same shape for decorator metadata (`host: {}, // host bindings`). Prettier moves the comment to its own line but never re-attaches it, so the comment permanently documents the wrong thing.
- **`no-leading-underscore-class-member`'s fixer only rewrites `this._x` reads, leaving every other reference to the renamed member dangling.** The `MemberExpression` visitor at `:108-115` requires `node.object.type === 'ThisExpression'` and `!node.computed`. Verified at runtime: `class Foo { private _value = 0; equals(other: Foo) { return other._value === this._value; } }` → `private value = 0; … return other._value === this.value;` (TS-private members are legally reachable on another instance of the same class, so this is valid input and broken output). Same failure for `const { _value } = this;` and `this['_value']`.
- **`class-member-order`'s fixer can emit unparseable code when members are not semicolon-terminated and share a line.** Segment concatenation (`:351`) relies on each member's own text ending the segment. Verified at runtime: `class C { focus() {}\n  private a = inject(A) }` → `class C {\n  private a = inject(A) focus() {} }`, which then reports `Parsing error: ';' expected.` (fatal) on re-lint. A 4000-case fuzz over semicolon-terminated members found 0 parse errors, so this is confined to non-Prettier-formatted input — but `eslint --fix` runs before Prettier in the documented workflow.
- **`no-screaming-case-local` double-reports the same identifier.** `VariableDeclarator` (`:71`) and the `[init.type="ArrowFunctionExpression"]` selector (`:94`) both fire for a SCREAMING_CASE arrow inside a function. Verified at runtime: `function outer() { const MY_HANDLER = () => {}; … }` produces two errors on the same location — `noScreamingCaseLocal` _and_ `noScreamingCaseFunctionName`.
- **`require-dollar-suffix` is purely name-shaped, with concrete false positives and misses in this repo's own idiom.** Verified at runtime — reported: `const merged = merge({}, defaults)` even with `import { merge } from 'lodash-es'` (also lodash `concat`/`zip`/`from`/`partition`), `const out = readable.pipe(gzip)` (Node stream), and `const parts = partition(src$, fn)` (RxJS `partition` returns a _tuple_, not an Observable). Not reported: `toObservable(mySignal)`, `this.subject.asObservable()`, `this.http.get('/users')`, and any function returning an Observable. `toObservable` is a first-class API in this SDK, so its absence from the creator list is a meaningful miss.
- **`no-screaming-case-local`'s second message is undocumented and contradicts the documented rationale.** `meta.docs.description` (`:58-59`) and `apps/docs/eslint/rules.md:15` describe only "inside function bodies", while `noScreamingCaseFunctionName` fires at _any_ scope — so a module-level `const MY_FACTORY = () => {}` is an error even though the rule's own header comment (`:6-8`) says "At module level, SCREAMING_CASE is fine for true constants". Verified at runtime.
- **`angular-decorator-property-order` sorts real Angular metadata keys it does not know to the very end, and disables itself entirely on a spread.** Unknown keys get `orderIndex = config.order.length` (`:138-139`); `standalone`, `interpolation` and `deferredImports` are missing from `DECORATOR_CONFIG.Component` (`:14-38`). Verified at runtime: `@Component({ standalone: true, selector, template })` → `standalone: true` is moved below `template`. Separately, `:114-119` returns early if _any_ element is a `SpreadElement`, so `@Component({ host: {}, selector: 'et-a', ...rest })` is not reported at all despite being clearly out of order (verified).
- **`class-constant-property` treats a `null`/`undefined`-initialised field that is only written from outside the class as a constant.** `protected activeId = null;` with no in-class assignment → `shouldBeReadonly` fix then an unfixable `shouldUseScreamingCase` (verified at runtime). Only _in-class_ writes suppress the report (`:325`), so a field written by a parent component, a template, or `Object.assign` is misclassified.

### Low

- The reordering fix leaves a stray blank line right after `class X {` (`class-member-order.spec.js:122-127` and `:138-144` encode this as expected output). Verified that Prettier in this repo removes it, so cosmetic churn only.
- `guard-return-newline` on a single-line guard (`if (!x) { doA(); return; }`) needs two `--fix` passes and lands on one-space indentation (verified). No spec covers it.
- `guard-return-newline` accepts a comment line as the required blank line: `doA();\n// bail out\nreturn;` is not reported (verified) because the check is a line-number gap, not an actual empty line.
- `no-empty-newlines-between-imports` replaces the gap with a bare `'\n'` (`:36`), producing mixed line endings in a CRLF file (verified).
- `meta.docs.recommended` is present only on `class-member-order`, `class-constant-property` and `no-screaming-case-local`; the other five omit it although all eight are `error` in `recommended`. Plugin-wide: 36 of 58 rule files declare it.
- `class-constant-property` is marked 🔧 in `apps/docs/eslint/rules.md:82`, but only the `shouldBeReadonly` half has a fixer; `shouldUseScreamingCase` never does.
- `no-leading-underscore-class-member` never sees `TSParameterProperty` (`constructor(private _svc: Svc)`), `TSAbstractPropertyDefinition`/`TSAbstractMethodDefinition`, `static` members, or `AccessorProperty` — all verified silent. `class-member-order` and `class-constant-property` are likewise blind to `accessor` fields (`accessor foo = 1` alongside one other member yields _no_ report at all, because the entry count drops below 2).
- Comment-policy (AGENTS.md allowlist) violations: `no-screaming-case-local.js:31` restates the regex; `:72,77,80,90-92` narrate the code below them; `guard-return-newline.js:40,44,48,51,61` do the same. The ❌/✅ file headers are a plugin-wide convention. `class-member-order.js:390-391` is a legitimate invariant comment.
- `src/configs/recommended.js:57` comments the `@typescript-eslint/naming-convention` block as "No `_` or `#` prefixes", but the block sets `leadingUnderscore: 'allow'` for `variable`/`parameter`/`property`/`parameterProperty`/`accessor` (`:73`) — the underscore ban for class members actually comes from `ethlete/no-leading-underscore-class-member`, which does not cover parameter properties.
- `class-constant-property.js:72` reads `callee.object.type` without the `!callee.computed` guard its twin in `class-member-order.js:66` has, so `signal[x]()` would be treated as a reactive initializer. Harmless, but the two helpers should not diverge.

Clean: all eight rules and their specs were read end to end and exercised through `Linter#verify` / `verifyAndFix` with `@typescript-eslint/parser`. The two reordering fixers survived randomized fuzzing: 4000 random well-formed class bodies produced **0** parse errors, **0** lost members, and **0** cases where the fixed output still reported — `sortMembers`' topological pass (`class-member-order.js:242-274`) genuinely converges with the pairwise `getOrderingConflict` check, dependency cycles correctly yield _no_ fix rather than a wrong one, and the "methods are hoisted so `this.method()` is not an ordering dependency" carve-out at `:390-403` works. 3000 random `@Component` metadata objects with leading/trailing/block comments and both comma styles produced **0** parse errors and **0** lost properties, so `angular-decorator-property-order`'s comma reconstruction is syntactically sound — only comment _placement_ moves. Decorator ranges are included in member ranges, so `@HostListener(...) onClick()` moves as a unit (verified). A combined `verifyAndFix` with six of these rules enabled at once converged in a single stable output with no fix loop. `no-empty-newlines-between-imports` correctly declines to touch gaps containing comments or intervening statements (`:29`). All eight rules are registered in `src/index.js` and set to `error` in `src/configs/recommended.js` with rows in `apps/docs/eslint/rules.md` whose 🔧 and severity columns match the code.

### Spec coverage

- Well covered: `class-member-order` has the load-bearing group cases, the two `this.method()`-in-initializer non-dependency regressions (`:32-49`), and the `injectFoo()` helper heuristic. `angular-decorator-property-order` covers both decorators, the `template`/`templateUrl` and `styleUrl`/`styleUrls` aliasing, the spread bail-out, a leading-comment move, and the single-line form. `class-constant-property` covers the `@Pipe` `transform` carve-out and the `writtenMembers` suppression. `no-empty-newlines-between-imports` covers the comment-preserves-the-gap case.

Also untested: the `body.length !== members.length` fix bail-out (the largest behavioral surprise in the rule), dependency cycles yielding no fix, and getters/setters/overloads. For `no-leading-underscore-class-member`: no test for two underscore members colliding on one fixed name (the High above), none for non-`this` references, none for `TSParameterProperty`/abstract/static/`accessor`. For `require-dollar-suffix`: no `let`/`var`, no non-RxJS `.pipe()`, nothing on `toObservable`. For `angular-decorator-property-order`: no unknown-key ordering, no trailing same-line comment.
- Specs encoding a defect: `class-member-order.spec.js:122-127` and `:138-144` bake the stray leading blank line into the expected output (cosmetic, Prettier-healed). `no-leading-underscore-class-member.spec.js:21-23` and `:26-28` assert the fix on `this.`-only references, which is exactly the narrow shape that hides the dangling-reference bug.

## Angular metadata

(require-on-push-change-detection, no-redundant-on-push-change-detection, require-view-encapsulation-none, prefer-concise-angular-host-directives, prefer-concise-angular-style-metadata, no-empty-angular-metadata-arrays, no-standalone-flag, no-legacy-angular-decorators, no-template-literal-before-inline-template)

### High

- **`no-redundant-on-push-change-detection` + `require-view-encapsulation-none` together leave an unused `ChangeDetectionStrategy` import that no further `--fix` pass can clear, so `nx lint --fix` ends with a hard `@typescript-eslint/no-unused-vars` error.** Root cause is the early bail at `no-redundant-on-push-change-detection.js:222` (`if (!variable || variable.references.length === 0) return;`): once the `changeDetection` property has been removed in an earlier pass, the specifier has zero references and the `redundantImport` report is never emitted again. Both rules are `error` in `recommended`, and the conflict is triggered whenever `require-view-encapsulation-none`'s import rewrite (`require-view-encapsulation-none.js:83`) collides with `getSpecifierRemovalRange`'s range in the same pass — which happens as soon as the metadata contains any property not in `COMPONENT_ORDER` (`imports`, `host`, `providers`, `hostDirectives`, `animations`, `standalone`) sitting between `styleUrl` and `changeDetection`. Verified at runtime: a component with `styleUrl` + `imports: [ButtonDirective]` + `changeDetection: ChangeDetectionStrategy.OnPush` → after `verifyAndFix` the import keeps `ChangeDetectionStrategy`, the property is gone, and the remaining error is `@typescript-eslint/no-unused-vars`. Independently, the same guard means a _pre-existing_ unused `ChangeDetectionStrategy` import is never reported at all (verified: zero messages).
- **`no-redundant-on-push-change-detection` deletes the `ChangeDetectionStrategy` import while leaving live references behind, producing code that does not compile.** `isOnPushChangeDetectionReference` (`no-redundant-on-push-change-detection.js:141-151`) accepts _any_ `X.OnPush` used as a `changeDetection:` property value — it never checks that the enclosing object is a `@Component` decorator argument — while the property-removal path (`isOnPushValue`, `:88-93`) requires the object to be literally named `ChangeDetectionStrategy`. Verified at runtime: (a) aliased import — `import { ChangeDetectionStrategy as CDS }` + `changeDetection: CDS.OnPush` → fixed output drops the import but keeps `CDS.OnPush` (TS2304); (b) `TestBed.overrideComponent(Foo, { set: { changeDetection: ChangeDetectionStrategy.OnPush } });` (a very common spec-file shape) → the import is deleted, the usage stays.
- **`no-standalone-flag` removes `standalone: false`, which is semantically load-bearing and whose removal breaks the build on Angular 19+.** The rule matches the key name only (`no-standalone-flag.js:80`) and never inspects the value; `meta.docs.description` (`:54-55`) justifies removal with "standalone is the default", which is only true for `standalone: true`. Stripping `standalone: false` turns an NgModule-declared component/directive/pipe into a standalone one and the compiler then rejects its `declarations` entry. Verified at runtime: `@Component({ selector: 'et-x', template: '', standalone: false })` → fixed output drops the flag. The spec **encodes this as correct** (`no-standalone-flag.spec.js:29-33`).
- **`no-legacy-angular-decorators` autofixes `@HostBinding(<non-literal>)` into a silently wrong host binding.** `no-legacy-angular-decorators.js:382-389` falls back to `memberName` whenever the first argument is not a plain string `Literal`, so a constant or an interpolated binding name is discarded. Verified at runtime: `const KEY = 'class.active';` + `@HostBinding(KEY) isActive = false;` → fixed to `host: { '[isActive]': 'isActive' }` — the `class.active` binding is gone, replaced by a nonexistent `[isActive]` property binding. Identical for a template-literal argument. The rule should decline to fix when the binding name is not statically a string.
- **Crash: `no-redundant-on-push-change-detection` throws a `TypeError` on `import ng, { ChangeDetectionStrategy } from '@angular/core';`.** `getSpecifierRemovalRange` (`no-redundant-on-push-change-detection.js:123-132`) guards only `importNode.specifiers.length === 1`; with a default specifier plus a single named specifier, line 131 evaluates `named[-1].range[1]`. Verified at runtime: `Cannot read properties of undefined (reading 'range')` — the whole file's lint run aborts. (Narrow trigger: only a default+single-named import from `@angular/core`.)
- **Four rules silently delete a `SpreadElement` from `@Component`/`@Directive` metadata, destroying source.** All of them build removal/insertion ranges from a `properties.filter(p => p.type === 'Property')` list and then use brace-to-brace or previous-property-to-property ranges that span the spread: `no-empty-angular-metadata-arrays.js:36-47`, `no-standalone-flag.js:36-47`, `no-redundant-on-push-change-detection.js:103-114`, and the `properties.length === 0` branches in `require-view-encapsulation-none.js:126-128` / `require-on-push-change-detection.js:172-174`. Verified at runtime: `@Component({ ...BASE, imports: [] })` → `@Component({})`; `@Component({ selector: 'et-x', ...BASE, standalone: true })` → `@Component({ selector: 'et-x' })`; `@Component({ ...BASE })` → `@Component({ encapsulation: ViewEncapsulation.None })`. The repo itself has no spread-in-metadata today (grepped), so this is latent here but live for consumers.

### Medium

- **No rule in this set verifies where `Component` / `Directive` / `Input` come from, so a same-named decorator from another package is reported — and `require-view-encapsulation-none` will inject an `@angular/core` import into a non-Angular file.** Detection is name-only (`require-view-encapsulation-none.js:207-217`, `require-on-push-change-detection.js:261-271`, `prefer-concise-angular-host-directives.js:15-25`, `no-empty-angular-metadata-arrays.js:19-29`, `no-standalone-flag.js:19-29`, `no-legacy-angular-decorators.js:35-40`, `no-template-literal-before-inline-template.js:98-106`). Verified at runtime: `import { Component } from 'some-other-lib';` + `@Component({ name: 'x' })` → reported and fixed with an added `@angular/core` import. The mirror-image false negatives are also confirmed: `import { Component as Cmp }` + `@Cmp({...})` and `import * as ng` + `@ng.Component({...})` produce no report from any of these rules.
