# Rich text editor headless scan - open findings

Scan of `libs/components/src/lib/forms/rich-text-editor/headless/` from 2026-09-28. 2 High, 11 Medium, 11 Low, 2 Spec. Verification: 13 of 13 High/Medium confirmed, 0 re-rated, 0 refuted. Skipped: the spec files (read only to judge coverage), and `markdownToHtml`/`htmlToMarkdown`/`isSafeLinkUrl` in `libs/core` (out of scope, but read far enough to confirm that the pasted and typed link hrefs pass `isSafeLinkUrl` on both sides of the pipeline). Paths are relative to `forms/rich-text-editor/`.

## Lists and blocks

- High: `outdentListItem` moves the item after its parent `<li>` but leaves the siblings that follow it in the old sublist, so the content changes order (`headless/internals/rich-text-editor-dom-lists.ts:267`). For `A > [B, C]`, Shift+Tab on B (or Enter on an empty nested middle item, through `exitListItem`) gives `A > [C], B`. Move B's following siblings into a new sublist under B, as `exitListItem` already does for top-level lists. S Verified (repro).
- Medium: `unwrapList` moves every child of each `<li>` into a `<p>`, including a nested `<ul>`/`<ol>`, and so produces `<p>text<ul>…</ul></p>` (`headless/internals/rich-text-editor-dom-lists.ts:21-28`). Toggling off a list that has nested items gives invalid markup that the Markdown pass flattens. Lift nested lists out as sibling blocks, or unwrap them recursively. S Verified (repro).
- Medium: `blocksInRange` treats each root child as a block, so a loose first line (Chrome keeps the first typed line as bare text before any `<p>`) like `foo <strong>bar</strong> baz` becomes three blocks (`headless/internals/rich-text-editor-dom-core.ts:261-272`). `toggleList` makes three list items (`dom-lists.ts:184-204`), `toggleHeading` three headings (`dom-headings.ts:87-95`), `toggleBlockquote` three `<br>`-split lines (`dom-blockquote.ts:107-117`), `toggleCodeBlock` three code lines (`dom-code-block.ts:88`); a collapsed caret converts only the text node that holds it. Group consecutive inline root children into one run before these commands, the way `wrapLineBeforeNativeDiv` does for serialization. M Verified (repro).
- Medium: block autoformat does not exclude `blockquote`, and inside a quote (quotes hold `<br>` lines, no `<p>`) `closestWithin(…, 'p, div')` returns the root, because `closestWithin` also matches the root `<div>` (`headless/internals/rich-text-editor-dom-autoformat.ts:35-39`). In a quote at the top of the document, `- `, `1. ` or `# ` on its first line turns the whole quote into a list or heading and drops the quote. Add `blockquote` to the exclusion list (or scope the prefix to the quote line). S Verified (repro), with a different outcome: quotes load as `<br>` lines, so the caret moves to the root start, `blocksInRange` finds no block, and the typed `-`/`#` is eaten while an empty list or heading is appended at the end of the document; the quote stays. A quote that holds a `<p>` does turn into a list and loses the quote.

## Inline marks and links

- Medium: `blockSlices` finds blocks with `'li, p, td, th'` only, so a selection across two headings, two Chrome `<div>` lines or two quote-free loose runs counts as one block (`headless/internals/rich-text-editor-dom-inline-marks.ts:23-28`). The `surroundContents` fallback then wraps the partial blocks: `<strong><h1>…</h1><h2>…</h2></strong>`, the exact shape the comment above it guards against. Use `HEADING_SELECTOR` and `div` in the block test as well. S Verified (repro).
- Medium: `applyLink` wraps a non-collapsed selection with `surroundContents` and falls back to `extractContents` without block slicing (`headless/internals/rich-text-editor-dom-links.ts:108-117`). A link over a selection across two paragraphs gives `<p>x<a><p>…</p><p>…</p></a></p>`. Reuse the inline-marks block slicing (one `<a>` per block), or refuse a cross-block link. M Verified (repro): the result is `<p>x</p><a><p>one</p><p>two</p></a><p>y</p>`; the link editor prefills `text` with the selection, so this path is the default one.
- Low: `insertInlineText` via `splitInlineAncestorsAtCaret` walks past an `<a>` to a mark outside it and splits the link into two anchors (`headless/internals/rich-text-editor-dom-inline-marks.ts:386-399`). A pending bold inside `**[link](x)**` serializes as two adjacent links. Stop the walk at `a`. S

## Paste and HTML parsing

- High: `insertNormalizedHtml` inserts multi-block content after the caret's top-level block, not at the caret (`headless/internals/rich-text-editor-dom-paste.ts:31-41`). Paste two paragraphs into `Hello |world` and you get `Hello world`, `A`, `B` instead of `Hello A`, `B world`; with the caret at a block start, or in the middle of a list item, the pasted blocks also land after the whole block or list. When the caret is directly on the root (`anchor === el`), `ref` is `null` and the content goes to the very end. Split the caret block at the range and insert between the halves. M Verified (repro).
- Medium: an HTML paste with the caret in a fenced code block puts marks inside `<pre><code>` (inline path) or puts blocks after the `<pre>` (`headless/rich-text-editor.directive.ts:635-666`, `headless/internals/rich-text-editor-dom-paste.ts:53-58`). Code blocks must stay literal text. In `pasteHtml`, when `markStates()?.codeBlock` is true, insert the clipboard's plain text instead. S Verified (repro).
- Medium: `codec.render` runs a regex over the whole HTML string, so `{{type:id}}` inside an attribute becomes chip markup inside that attribute (`headless/internals/rich-text-editor-token.ts:136-141`). A link to `https://x/{{user:1}}` (typed into the link editor, or pasted) renders as `<a href="https://x/<span class="…">…` and corrupts the markup on the next render (undo, external write). The escaping holds, so no script injection, but content breaks. In addition, `parseTokenText` runs over the Markdown of an HTML paste (`headless/rich-text-editor.directive.ts:651`), so `[x](https://site/#intro)` turns into a token when a `#` trigger has an item `intro`, and code spans get chips too. Render and parse tokens only in text nodes. M Verified (repro).
- Low: `serializeCleanHtml` rewrites only bare `<div>` openers but every `</div>` closer, so a `<div class="…">` leaves an opener without its match (`headless/rich-text-editor.directive.ts:827-828`). Re-tag `div` elements on the clone in the DOM instead of a string replace. S

## Token triggers

- Medium: `resolveTriggerItems` calls `trigger.items(query)` as soon as `switchMap` receives the request, and only the subscription is delayed (`headless/internals/rich-text-editor-trigger-source.ts:58,82,102-105`). A Promise source (a `fetch`) fires one request per keystroke, so `debounceTime` does nothing for it. Wrap the call in `defer(() => resolveTriggerItems(…))`. S Verified (repro).
- Medium: a `trigger.items` function that throws synchronously errors the outer stream, because the throw happens in the `switchMap` project and not inside `fetch$`'s `catchError` (`headless/internals/rich-text-editor-trigger-source.ts:58`). `toSignal` then rethrows on every `itemsState()` read and the triggers stop for the life of the editor. The `defer` fix above also routes the throw into `catchError`. S Verified (repro).
- Medium: `deletePrecedingChip` runs on Backspace without a `disabled`/`readonly` check, and `syncFromDom` writes the value (`headless/rich-text-editor-triggers.directive.ts:247,340-361`). In a readonly editor (focusable, `tabindex=0`), a click right after a chip followed by Backspace removes the chip and changes the form value. Return early when the editor cannot edit. S Verified.
- Medium: `hydrate` re-resolves every chip in the root on each paste, token insert, undo and external write, and `void resolved.then(apply)` has no rejection handler (`headless/internals/rich-text-editor-token.ts:143-170`; callers `headless/rich-text-editor.directive.ts:661,689,771,906`). With an async `resolveItem`, a document with N chips sends N requests per paste, and a rejected lookup is an unhandled rejection. Hydrate only new chips (or cache labels per `type:id`), and catch rejections. M Verified.
- Low: `listenersAttached` stops the listeners from attaching again, so after `attachEditable` receives a new element the triggers keep their listeners on the old root (`headless/rich-text-editor-triggers.directive.ts:139-146`). Use `effect` + `onCleanup` like the floating toolbar does. S
- Low: `aria-activedescendant` points at `…-option-0` while the popup shows loading, "No results" or an error, where that option does not exist (`headless/rich-text-editor-triggers.directive.ts:156-170`). Set it only when items exist. S

## Selection and history

- Low: `restoreSelection` adds `lastRange` back without the `el.contains(…)` check that `ensureCaret` does (`headless/internals/rich-text-editor-dom-core.ts:72-82`). After an external value write, `innerHTML` replaced the nodes, so a toolbar command from an unfocused editor restores a detached range and silently does nothing. Fall back to `ensureCaret()` when the range is stale. S
- Low: ordered-list autoformat drops the typed start number: `3. ` gives a list that starts at 1 (`headless/internals/rich-text-editor-dom-autoformat.ts:53`). Set `start` on the `<ol>`, if the Markdown pass keeps it. S
