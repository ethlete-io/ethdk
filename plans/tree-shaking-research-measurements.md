# Tree-shaking measurements - `@ethlete/{core,query,components}`

Measured 2026-07-31 against the **working tree as-is** (uncommitted bracket layout refactor), from
`/Users/tom/dev/ethlete-sdk/dist/libs` built at 23:03 by `npx nx build core query types components`.
`@ethlete/cdk` and `@ethlete/contentful` are out of scope and were not measured.

> Caveat: `libs/components`, `libs/core` and `libs/types` were verified untouched since that build, so
> every `components`/`core` number is exact for the tree as it stands. `libs/query` picked up
> concurrent edits (auth tracking, multi-tab sync, a new `query-invalidation.ts`) _after_ the 23:03
> build, so the query byte counts may drift by a small amount; none of the structural findings depend
> on them.

All numbers are **gzip level 9 bytes in `--external` mode** - every non-`@ethlete` package
(`@angular/*`, `rxjs`, `date-fns`, …) is marked external, so the number is "how much `@ethlete` code
lands in the app", without the ~85 kB gz Angular runtime constant. Deltas are identical in full mode.

Pipeline (unchanged from `bracket-bundle-baseline.md`): ng-packagr FESM → `@angular/compiler-cli`
linker + `@angular/build`'s babel optimizer passes → esbuild `minify` + `treeShaking` +
`define ngDevMode=false` → gzip.

## 2. The PURE fix, quantified - and the surprise

### 2a. `/*#__PURE__*/` on the provider/label factories buys **exactly zero**

| variant     | what was annotated                                                                                                                            | # decls | core floor | query floor |  components floor |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ------: | ---------: | ----------: | ----------------: |
| **current** | -                                                                                                                                             |       - | **12 800** |  **19 080** |        **91 983** |
| `pure-A`    | `createLabels`, `createStaticRootProvider`, `createRootProvider`, `createProvider`, `createStaticProvider`                                    |      88 |     12 800 |      19 080 | **91 983 (±0 B)** |
| `pure-B`    | A + `memoizeSignal`, `createPropertyBinding`, `createManagedMetadataKey`, `create{,Secure}QueryTemplate`, `create{,Secure}GqlCreatorTemplate` |     137 |     10 292 |      10 931 |  85 934 (−5.9 kB) |
| `pure-C`    | B + `new Set/Map/WeakMap/Date`, `Symbol`, `Object.keys`, `signal`                                                                             |     165 |     10 260 |      10 875 |  85 844 (−6.0 kB) |

**Tier A moves nothing at all - not one byte.** The reason is structural, not a missing annotation:
all 88 of those declarations are **array-destructuring** declarations, and esbuild will not remove a
destructuring declaration however pure the initializer is. Minimal repro
(`esbuild-probe/`, esbuild from this repo, `treeShaking: true`, `sideEffects: false`):

```js
const HEAVY = { a: 'aaaaaaaaaa' };
const mk = () => [() => HEAVY, () => HEAVY];
export const tiny = 42;

export const [provideOne, injectOne] = /*#__PURE__*/ mk(); // ❌ kept (array destructuring)
export const [provideThree, injectThree] = mk(); // ❌ kept
export const { p: provideFour } = /*#__PURE__*/ mk(); // ❌ kept (object destructuring)
const t = /*#__PURE__*/ mk();
export const provideTwo = t[0]; // ❌ kept (`t[0]` = possible getter)

export const provideFive = /*#__PURE__*/ mkProvide(); // ✅ dropped
export const injectFive = /*#__PURE__*/ mkInject(); // ✅ dropped
```

Only the last shape - **one PURE call per exported binding, no destructuring and no index/property
read** - is removable. esbuild treats both the iterator protocol of array destructuring and any bare
property read as a potential side effect.

Tier C (`new Set` / `new Map` / `new Date` / `Symbol`) is worth **90 B gz** on the components floor.
Counted: 11 in components, 12 in core, 3 in query. **They do not matter** - they are small leaves.
The one exception is `const LAYOUT_KEYS = Object.keys(BRACKET_DEFAULTS)`, which pins the 866-B
bracket defaults table (1 169 B exclusive unmin).

### 2b. Fixing the shape: the actual win

`split-tuples.mjs` rewrites every one of the 88 tuple declarations into a memoized per-binding shape,
i.e. what the real fix has to look like:

```js
const __etTup0 = () => createRootProvider(/* …unchanged args… */); // arrow decl: droppable
const provideX = /*#__PURE__*/ __etTupleGet(__etTup0, 0); // droppable when unused
const injectX = /*#__PURE__*/ __etTupleGet(__etTup0, 1);
const X_TOKEN = /*#__PURE__*/ __etTupleGet(__etTup0, 2);
```

`__etTupleGet` memoizes on a `WeakMap`, so there is still exactly one `InjectionToken` per
declaration - runtime semantics preserved.

| --------------------------------------- | ---------------: | ---------------: | -------------------: | ---------------------: |

| `pure-A`                                |           12 800 |           19 080 |               91 983 |                      0 |

### 2c. Residual after the fix: the third blocker class

`retention.mjs` on the fixed floor (20 300 B unmin / 4.9 kB gz): 8 roots left. The biggest are
**top-level object/array literals containing a member access**, which esbuild also refuses to drop
(a property read may invoke a getter). Same mechanism, third syntax:

```js
const RICH_TEXT_EDITOR_TOOL_BUTTONS = { undo: { label: DEFAULT_RICH_TEXT_EDITOR_LABELS.undo, … } };
const BRACKET_DENSITY_PRESETS = { [BRACKET_DENSITY.DEFAULT]: … };   // computed key from a const-object enum
```

14 such declarations in `components`, 0 in `core`, 0 in `query`. Wrapping them in a PURE IIFE
(`wrap-literals.mjs`) takes the fixed floor from 4 989 → 3 253 B gz (**−1.7 kB**). Largest
offenders by unmin statement bytes: `RICH_TEXT_EDITOR_TOOL_BUTTONS` 2 911, `DEFAULT_RICH_TEXT_EDITOR_LABELS`
2 031 (pulled by the former), `BRACKET_DEFAULTS` 866, `BRACKET_DENSITY_PRESETS` 424,
`RICH_TEXT_EDITOR_HEADING_OPTIONS` 414, `BUTTON_SPINNER_CONFIG` 363,
`WINDOW_CONTROL_BUTTON_SPINNER_CONFIG` 288, `LAYOUT_FACTORY_SUGGESTION` 255,
`TERMINAL_ROUND_SORT_PRIORITY`, `PRESSED_VARIANT_MAP` ×2.

**Caveat on the `current` column: it is not a usable ranking.** Because the floor already pins
button, notification, overlay, spinner, PiP and the RTE DOM engine, on today's tree importing
`ButtonComponent` costs **0 B**, importing the whole notification domain costs **35 B**, and each
overlay strategy costs **~40 B**. Those are not cheap features - they are features you already paid
for. Any per-feature work prioritised off today's numbers would be prioritised off noise. Fix the
floor first, then the `fixed` column is the real map.

There is no `combobox`/`autocomplete` domain (searchable select is `SELECT_IMPORTS` +
`SelectSearchDirective`); dialog and bottom-sheet are overlay _strategies_, not domains.

## 4. Top 5 opportunities by measured bytes

1. **Stop returning destructurable tuples from `createProvider` / `createRootProvider` /
   `createStaticProvider` / `createStaticRootProvider` / `createLabels` - 88 declarations.**
   Measured: components floor **89.8 → 10.7 kB gz** (−79.2 kB), core **12.5 → 6.9**, query
   **18.6 → 12.9**. Every consumer of every `@ethlete` package gets this. Worth more than everything
   else on this list combined, and `/*#__PURE__*/` alone provably does not deliver it (§2a) - the
   emitted shape must become one PURE call per binding.
2. **PURE-annotate (or restructure) the remaining single-binding factory calls - 49 declarations.**
   `memoizeSignal` ×25 (core), `create{,Secure}QueryTemplate` ×10 + `create{,Secure}GqlCreatorTemplate`
   ×8 (query), `createPropertyBinding` ×5 (core), `createManagedMetadataKey` ×1. Measured on top of
   #1: components **10.7 → 4.9 kB** (−5.9 kB), core **6.9 → 1.1**, query **12.9 → 0.9**. For
   `@ethlete/query` this is actually the _larger_ of the two fixes. Cheap: these are already
   single-binding, so a literal `/*#__PURE__*/` (or a `markTopLevelPure` allowlist) is enough.
3. **Rich-text-editor: 73.8 kB gz for the base import** (`RICH_TEXT_EDITOR_IMPORTS`), +1.0 kB per
   alignment tool, +3.6 kB for the table tool. Nearly twice the next-largest domain, and today
   ~40 kB of it is force-fed to every `@ethlete/components` consumer via `provideRichTextEditorDom`
   (root #2, 60 kB exclusive unmin). After #1 it is opt-in, but it is still by far the heaviest
   domain and the obvious candidate for splitting the DOM engine per feature
   (`rich-text-editor-dom-{core,inline-marks,blockquote,…}.ts` are already separate files).
4. **The overlay domain and its strategies: 18.2 kB base + 16.7–20.5 kB per strategy.**
   `overlay-container.component.html` alone compiles to 16.9 kB min - the single largest source unit
   in the floor. Six strategies (`dialog`, `bottom-sheet`, `fullscreen`, `left/right/top-sheet`,
   `anchored`) each cost about as much as the base, and `fullscreen-animation.ts` is 8.8 kB min on
   its own. Today all of them are in every import; after #1 a consumer using only
   `dialogOverlayStrategy` should not pay for `fullscreen-animation.ts` - verify the strategies do
   not cross-reference.
5. **`select` 38.7 kB / `cascader` 39.8 kB, and the `components/stream` PiP chain 34.5 kB.**
   `SELECT_IMPORTS` is 20 symbols and costs 2.8× `form-field + input` (15.7 kB); worth a lean
   `*_IMPORTS` split like `table` already did (14 separate import arrays, and `table` measures a
   comparatively modest 18.9 kB). The stream/PiP chain is 47.8 kB min in the floor today, pinned by
   `providePipChromeManager` - that root also pulls `ResizeHandlesComponent` out of `@ethlete/core`.

Runners-up, both cheap: **the 14 literal-with-member-access declarations** (−1.7 kB on the fixed
floor, §2c - mostly `[SOME_ENUM.KEY]:` computed keys that could be string literals), and
**`provideQueryErrorLabels`**, which drags 14.2 kB min of German + English HTTP-error message tables
into every import today (19 kB exclusive unmin, root #6).

## 5. Measurement surprises

- **`/*#__PURE__*/` on the provider/label factories is worth literally 0 bytes.** The earlier
  `bracket-bundle-baseline.md` conclusion ("annotating those factories `/*#__PURE__*/` … is the
  single highest-leverage fix") is right about _where_ the mass is and wrong about the _mechanism_.
  The blocker is the destructuring, not the missing annotation.
- **Three distinct syntactic blockers, one root cause** (esbuild will not drop a statement whose
  initializer might invoke a getter or an iterator): array/object destructuring (88 decls), index or
  property reads (`t[0]`, `X.y`, 14 decls), and un-annotated factory calls (49 decls). Only the
  third is fixable with a comment.
- **98 % of the components floor and 98 % / 97 % of the core / query floors are reachable from the
  root set, and 0 B is reachable only from the entry.** The floor is not "shared infrastructure the
  entry needs" - it is retention, end to end.
- **`reach` ≫ `exclusive` for nearly every root** (`providePipChromeManager`: 210 kB reach, 1.5 kB
  exclusive). Fixing roots one at a time would show almost no movement; that is very likely why this
  has gone unfixed. It has to be done as one sweep.
- **The current per-feature numbers are actively misleading.** `ButtonComponent` measures 0 B,
  the notification domain 35 B, each overlay strategy ~40 B - because the floor already paid.
- **`@ethlete/query`'s floor is mostly `@ethlete/core`'s floor** (12.5 of 18.6 kB), and its top 8
  retention roots are core's, not query's.
- **A tuple's two halves can be shaken apart.** In the fixed variant the bracket entry keeps
  `injectBracketLabels` and drops `provideBracketLabels` - per-binding granularity is real, so an
  app that never calls `provideXLabels` stops paying for the default label table.
- **`libs/query/src/lib/pipes/parse-http-error-code-{de,en}.ts`** - 14.2 kB min of localized error
  strings - is in every `@ethlete/components` import today, via one `createLabels` call.
